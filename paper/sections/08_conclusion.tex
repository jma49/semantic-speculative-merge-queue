\section{Conclusion}
\label{sec:conclusion}
Under identical unstacked exact-tree commit verification ($W{=}8$, decoupled generic priors), historical co-change cone exclusion does not produce a reliable net improvement over disabling exclusion. Unfiltered cones collapse root batch width and severely degrade both survivor latency and clean false rejections. Filtering warm-up mega-PRs and directory cliques (\texttt{SSMQ-FilteredCone}) cures cone density explosion (\UnfDensity{}\% $\to$ \FcDensity{}\%) and recovers most of the unfiltered penalty, yet still fails to outperform \texttt{SSMQ-NoCone} consistently: a modest nominal P95 shift (\FcNomDeltaP{}~min, sign $p{=}\FcNomSignP{}$) coincides with higher clean FRR (\FcNomDeltaFrr{}~pp) and fewer accepted PRs, while saturated, directory-proxy, and uniform-null regimes are null or slower. Inside the same unstacked family, adapting \texttt{Beheshtian-BatchStop4} likewise increases stale rechecks and FRR relative to bisection. Although single-timeline stacked policies eliminate stale rechecks, membership-partition differences in transient pair fault semantics prevent drawing causal cross-architecture rankings from these simulator profiles.

Our \ObsDays{}-day audit of native GitHub Merge Queues across TypeScript and Cargo (\ObsDistinctPrs{} distinct PRs, \ObsAdmissions{} admissions; \ObsTsWfSelected{} selected TypeScript \texttt{merge\_group} workflow runs at \ObsTsWfP{}~min median) confirms non-trivial re-enqueue and eviction rates while demonstrating why discordant fetch-time versus queue-tested heads preclude PR-causal attribution from public API logs. Executable Git and QuixBugs experiments confirm a narrower localization boundary: AST function ranking improves over weight-matched file ranking specifically on co-file sibling edits, which file-disjoint packing removes. Determining which queue architecture dominates in production will require field telemetry capturing enqueue-time head OIDs, multi-PR batch membership, and exact revalidation outcomes.
