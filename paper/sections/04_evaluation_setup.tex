\section{Evaluation Setup}
\label{sec:eval_setup}

We evaluate SSMQ across five research questions designed to test attribution precision, end-to-end systems performance, non-circularity, component contributions, and theoretical regime boundaries:
\begin{itemize}
    \item \textbf{RQ1 (Causal Blame Micro-Benchmark)}: How accurately and rapidly does \texttt{ASTStackCausalRanker} isolate single-PR regressions, co-file distractors, and verified pairwise semantic conflicts on real executed Python failures relative to file-level traceback matching?
    \item \textbf{RQ2 (End-to-End Queue Performance)}: How does SSMQ compare against serial, static FIFO batching, linear speculation, outcome-tree SubmitQueue, and fixed-retry baselines in merge throughput, P95 latency, CI compute cost, and repository/velocity scaling?
    \item \textbf{RQ3 (Non-Circularity Under Off-Graph Conflicts)}: Do SSMQ's tail-latency and cost advantages persist when up to $60\%$ of semantic conflicts occur outside $\hat{G}$, and how does SSMQ perform on a zero-conflict control ($P_c = 0$)?
    \item \textbf{RQ4 (Ablation \& Flaky Pareto Frontier)}: What is the isolated contribution of each SSMQ mechanism, and how effectively does two-regime Beta-Binomial gating balance P95 latency against clean-PR false rejections across $\phi \in [0\%, 15\%]$?
    \item \textbf{RQ5 (Failure-Density Regime of 1-Step Blame)}: Across rising defect densities and batch caps, where does 1-step causal blame significantly outperform binary bisection, and where does it saturate under multi-culprit failures (Proposition~\ref{prop:complexity})?
\end{itemize}

\subsection{Real Executable 64-Batch Python Blame Micro-Benchmark}
Rather than postulating synthetic attribution rates, we build an executable six-module Python commerce codebase (\texttt{pricing}, \texttt{inventory}, \texttt{shipping}, \texttt{auth}, \texttt{ledger}, \texttt{checkout}; $18$ functions plus an end-to-end integration test suite) and run \BenchTotalBatches{} failing multi-PR batches (sizes $4$--$8$ PRs) through real subprocess \texttt{unittest} executions:
\begin{enumerate}
    \item \textbf{\BenchSingleBatches{} Disjoint Single-PR Regressions}: $12$ distinct functional defects spanning all six modules bundled alongside benign functional-AST PRs (input validation guards, fast-path branches, and schema metadata additions).
    \item \textbf{\BenchCofileBatches{} Co-File Distractor Regressions}: Functional defects paired in the same batch with a benign comment or docstring PR modifying the \emph{identical file} at higher line churn ($+3$ lines vs.\ $+1$ line), testing whether AST symbol diffing separates non-executable edits from behavioral changes.
    \item \textbf{\BenchSemBatches{} Verified Pairwise Semantic Conflicts}: $6$ cross-file interaction pairs verified automatically to satisfy the strict semantic-conflict invariant---\emph{PR~$A$ passes alone, PR~$B$ passes alone, and $A+B$ fails integration tests}---covering rounding precision drift, luxury-tax tier non-linearity, in-place dictionary mutation against immutability assertions, whitespace normalization contracts, order-ID casing invariants, and strict boolean typing.
\end{enumerate}

Four deterministic rankers process the exact resulting Python stack traces: \texttt{RandomRanker}, \texttt{ChurnRiskRanker} (descending line churn), \texttt{FileTracebackOverlapRanker} (a strong non-AST baseline matching stack-frame file paths and failing test module names with churn tie-breaking), and \texttt{ASTStackCausalRanker} (Algorithm~\ref{alg:blame}).

\subsection{Real OSS Trace Replay and Decoupled Conflict Oracle}
Our end-to-end discrete-event simulator replays the 600 chronologically merged GitHub PRs characterized in Table~\ref{tab:trace_summary}. To enforce strict temporal separation, the earliest $25\%$ of commits ($50$ PRs per repository) populate $\hat{G}$ and calibrate risk normalization; the remaining $75\%$ ($450$ evaluation PRs across the three repositories) drive the arrival stream, preserving empirical inter-arrival spacing scaled to mean offered load $6.0 \times v$~PRs/hr ($v \in \{1\times, 3\times, 5\times, 10\times\}$). Simulated CI clusters provision $W=8$ parallel runners with job durations drawn from $\mathcal{N}(12.0, 2.0^2)$~min, risk-weighted individual PR defect rates calibrated to mean $8\%$, and SSMQ's attribution accuracy and runtime parameterized directly from our 64-batch benchmark measurements (\BenchASTTopOnePct{}\% Top-1, \BenchASTTopTwoPct{}\% Top-2, \BenchASTMs{}~ms).

To prevent circular coupling between conflict generation and graph-disjoint packing, the simulator separates the \emph{ground-truth conflict oracle} $G^*$ from the scheduler's observed graph $\hat{G}$ through a controllable recall parameter $\rho \in [0.40, 1.00]$:
\begin{itemize}
    \item \textbf{On-Graph Conflicts}: Sampled at edge density $P_c = 0.18$ over PR pairs whose observed cones intersect in $\hat{G}$.
    \item \textbf{Off-Graph Latent Conflicts}: Sampled across \emph{cone-disjoint} PR pairs outside $\hat{G}$ (weighted $4\times$ higher within the same top-level subsystem) such that a $(1-\rho)$ fraction of all true semantic conflicts remain invisible to SSMQ's batch packer. At the nominal $\rho = 0.80$ operating point, $20\%$ of conflicts are unobservable off-graph interactions; at $\rho = 0.40$, $60\%$ lie outside $\hat{G}$.
    \item \textbf{Persistent vs.\ Intra-Batch Conflicts}: $3\%$ of conflicts represent \emph{persistent} mainline incompatibilities that continue to fail after sequential rebase and must be rejected, whereas $97\%$ represent rebase-resolvable intra-batch interference that passes once serialized.
\end{itemize}

\subsection{Baselines, Ablations, and Paired Statistical Inference}
We compare \textbf{SSMQ} against five production-representative schedulers and three single-component ablations:
\begin{itemize}
    \item \texttt{SerialQueue}: Strictly sequential single-PR verification ($W=1$).
    \item \texttt{StaticBatchBisect}: Arrival-ordered static batching ($K_{\max}=8$) with recursive binary bisection upon failure, representative of Bors and GitHub Merge Queue~\cite{fallahzadeh2023accelerating}.
    \item \texttt{SpeculativeLinear}: Prefix-based speculative pipeline ($D_{\max}=4$, modeling GitLab Merge Trains) that aborts and restarts downstream prefixes upon an upstream failure.
    \item \texttt{UberSubmitQueue}: Faithful implementation of Uber's EuroSys~'19 outcome-tree scheduler~\cite{ananthanarayanan2019keeping}, speculating across pass and fail branches ranked by expected merges per CI minute and accounting for partial runner consumption on canceled nodes.
    \item \texttt{FlakeAwareBatch}: Arrival-ordered static batching augmented with an unconditional single rerun before bisection~\cite{henderson2023flake}.
    \item \texttt{SSMQ-NoGraph}, \texttt{SSMQ-NoFlaky}, \texttt{SSMQ-NoBlame}: Controlled ablations deactivating graph-disjoint risk lanes, two-regime Beta-Binomial flaky gating, or 1-step AST causal blame, respectively.
\end{itemize}

All \TotalSealedRuns{} experimental suites (\TotalSealedRecords{} simulation runs plus \BenchTotalBatches{} executed Python failure batches) evaluate $20$ paired random seeds per repository, sharing identical per-PR defect, pairwise conflict, and persistence realizations within each $(\text{repo}, \text{seed})$ block. Every run manifest is sealed with its Git commit SHA and SHA-256 digests over harness code, trace datasets, and output metrics. Our deterministic verification pipeline checks zero cumulative mainline escapes (\TotalEscapedDefects{}), computes $95\%$ percentile bootstrap confidence intervals ($2{,}000$ resamples), applies paired two-sided Wilcoxon signed-rank tests with Holm-Bonferroni family-wise error control, and reports non-parametric Cliff's $|\delta|$ effect sizes. Disjoint 20-seed A/A calibration (\texttt{v3\_exp1\_aa\_noise}) bounds inter-block stochastic drift at \AANoiseThroughputPct{}\% for throughput, \AANoiseLatencyPct{}\% for P95 latency, and \AANoiseComputePct{}\% for CI compute cost.
