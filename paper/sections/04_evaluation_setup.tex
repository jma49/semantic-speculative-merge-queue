\section{Evaluation Design}
\label{sec:eval_setup}
\subsection{Trace-driven exact-tree queue experiment}
We divide each chronological window into a warm-up prefix (earliest 25\%, 50 PRs) and an evaluation suffix (150 PRs). The prefix supplies risk scales and file neighborhoods. Each seed defines a paired workload shared across policies. Inter-merge gaps preserve the relative spacing of the suffix and are normalized to a baseline mean rate of six changes per hour before the velocity multiplier. We evaluate $W=8$ workers with jobs centered at twelve minutes under two arrival regimes: a \textbf{nominal} load ($5\times$, 30~PRs/hr, below singleton capacity of 40~PRs/hr) and a \textbf{saturated} load ($15\times$, 90~PRs/hr, well above singleton capacity so batching is necessary for queue stability). Each run drains the finite arrival stream.

The main condition injects unary defects using the risk score and constructs conflicts with a specified fraction of edges visible to the scheduler. A pair can interfere only inside a batch (marking both endpoints as culprits) or persist after one member lands. The default environment sets baseline defect rate $0.08$, pair sampling probability $0.18$, persistence share $0.03$, and transient test failure probability $0.05$. Crucially, \textbf{all scheduler priors are decoupled from these ground-truth rates}: the scheduler uses fixed generic priors ($\hat{q}_0=0.10$, $\hat{p}_c=0.10$, $\hat{p}_{\text{persist}}=0.02$) and its online $\mathrm{Beta}(\alpha,\beta)$ flake posterior. Every policy enforces \textbf{identical exact-tree commit verification} (Proposition~\ref{prop:safety}, zero commit-time oracle): a passing run may advance mainline only if the exact tree it tested equals the resulting mainline tree; otherwise it is invalidated and re-tested atop the new mainline. The simulator models suspect selection probabilistically (configured Top-1 and Top-2 probabilities $0.85$ and $0.95$) because public merge records lack CI tracebacks.

We compare ten exact-tree policies spanning unstacked batching, component ablations, and single-timeline stacking:
(1)~\emph{Parallel singleton + retry} ($K=1$, adaptive retry, zero graph/risk/blame);
(2)~\emph{FIFO batch + bisect} ($K\le 8$, bisection, no retry);
(3)~\emph{FIFO batch + retry} ($K\le 8$, adaptive retry, bisection);
(4)~\emph{FIFO + retry + blame} (\texttt{SSMQ-NoGraph}: adds blame without cones or risk lanes);
(5)~\emph{Risk + retry + blame} (\texttt{SSMQ-NoCone}: risk lanes without cone exclusion);
(6)~\emph{Disjoint batch + retry} (cone-disjoint packing + adaptive retry + bisection);
(7)~\emph{SSMQ without risk lanes} (\texttt{SSMQ-NoRisk});
(8)~\emph{SSMQ without blame} (\texttt{SSMQ-NoBlame});
(9)~\emph{SSMQ (full)}; and
(10)~\emph{FIFO outcome tree} (single-timeline speculative outcome tree with decoupled priors, natively exact-tree compliant because each child stacks onto its parent's exact commit prefix).
We deliberately \textbf{omit multi-lane outcome trees and per-PR DAG baselines} from exact-tree comparisons: because independent lanes and partial-ancestor DAGs omit concurrent non-overlapping commits from their tested base, they cannot commit independently under strict exact-tree verification without either an unrealizable commit oracle or cross-lane invalidation.

\subsection{Sensitivity, metrics, and paired inference}
In the recall sweep, each seed and repository receives an edge budget feasible at both endpoints of the sweep, including dense TypeScript; we vary how much of that budget lies on $\hat{G}$. Separate controls generate pair labels from evaluation-directory structure (at both nominal and saturated loads, plus no-flake and no-persistence variants) or uniformly over pairs, independently of $\hat{G}$ and with uniform unary defect risk. Within each condition, we contrast SSMQ against \texttt{SSMQ-NoCone}.

We summarize latency by averaging per-run survivor P95 latency across the 60 paired blocks (20 seeds $\times$ 3 repositories), and always disclose \textbf{mean root batch width}, \textbf{clean false-rejection rate (FRR)}, \textbf{accepted PRs}, \textbf{runner-minutes per merge}, \textbf{invalidation share}, and \textbf{per-repository contrasts}. Uncertainty intervals use 10,000 bootstrap resamples of the 20 paired seed blocks retaining all three repositories at equal weight.

\subsection{Executable experiments}
The Git factorial crosses two packing policies (FIFO or file-disjoint, $K\le 4$) with three recovery policies (bisection, matched nested file ranker, or AST ranker) on a 13-function Python repository. To eliminate lexical ID coding (\texttt{pr\_c*} $<$ \texttt{pr\_d*} $<$ \texttt{pr\_s*}), each 12-PR seeded stream receives role-neutral IDs (\texttt{pr\_00}..\texttt{pr\_11}) evaluated under \textbf{both ascending and descending polarities} across 10 seeds (20 paired streams per arm, 120 real Git replays). Both file and function specificity weights share the same $1.5\times$ direct-callee bonus so the file ablation isolates granularity alone. A separate concurrent protocol executes two Git worktrees in parallel on base $M_0$, advances \texttt{main} with the first passing commit, and tests whether accepting the second stale pass breaks \texttt{main} versus an exact-tree recheck.

To evaluate suspect ranking beyond a single Git replay, we report both (i)~the stratified 86-batch authored Python benchmark (disjoint defects, co-file comments, 50/50 ID-counterbalanced co-file functional siblings, and pairwise semantic conflicts) and (ii)~an independent adaptation of 6 published QuixBugs Python faults~\cite{lin2017quixbugs} with upstream test vectors (one knapsack input exceeds the memory cap) across sibling-function, same-function, and two-fault regimes under paired ID reversals (36 cases), plus trace-withheld controls. Case construction and neutral \texttt{pass} distractors remain ours; all executable ranker tests are scoped to single-file or small-module synchronous bare-name Python functions.
