\section{Evaluation Design}
\label{sec:eval_setup}
\subsection{Trace-driven exact-tree protocol and decoupled priors}
Each 200-PR chronological window is split into a warm-up prefix (earliest 25\%, 50 PRs, supplying risk scales and warm-up graphs) and an evaluation suffix (150 PRs). Paired workloads are shared per \texttt{(repo, seed)} across all policies. Inter-merge gaps preserve relative spacing normalized to 6~PRs/hr before multiplying to \textbf{nominal} ($5\times$, 30~PRs/hr, below singleton capacity of 40~PRs/hr at $W{=}8$ workers with $12\pm 2$~min Gaussian jobs) and \textbf{saturated} ($15\times$, 90~PRs/hr, where batching is required for stability) arrival streams, each drained to completion.

The default fault model injects unary defects (baseline rate $0.08$, risk-correlated in plausible regimes) and pairwise conflicts (sampling rate $0.18$, persistent share $0.03$, on-graph recall $0.80$) plus $0.05$ transient job flakiness. Crucially, \textbf{all scheduler priors are decoupled from ground-truth rates} (fixed generic $\hat{q}_0{=}0.10$, $\hat{p}_c{=}0.10$, $\hat{p}_{\text{persist}}{=}0.02$, $\mathrm{Beta}(1,19)$ flake prior), and \textbf{every policy enforces identical exact-tree commit equality} (Proposition~\ref{prop:safety}, zero commit-time oracle, zero escaped defects). Suspect selection in simulation uses configured Top-1/Top-2 probabilities ($0.85$/$0.95$) because public traces lack tracebacks.

\subsection{Grounded comparator methodology and missing inputs}
To evaluate SSMQ alongside published batching and queue designs without misrepresenting proprietary services, our v8 suite runs 12 exact-tree policies under identical capacity ($W{=}8$, $K{\le}8$, $D{\le}4$) and paired \texttt{GroundTruth} (with exact numerical parity verified on all 6 frozen v7 controls):
(1)~six v7 controls (\texttt{SSMQ}, \texttt{SSMQ-NoCone}, \texttt{FIFOBatchRetry}, \texttt{StaticBatchBisect}, \texttt{SpeculativeLinear}~\cite{zuul2026gating}, and single-timeline \texttt{FIFOOutcomeTree}~\cite{ananthanarayanan2019keeping}; v7 also ran \texttt{ParallelSingletonRetry}, \texttt{DisjointBatchRetry}, \texttt{SSMQ-NoRisk}, and \texttt{SSMQ-NoBlame});
(2)~\texttt{SSMQ-FilteredCone}, our v8 mechanism diagnostic dropping warm-up mega-PRs ($>20$ files) and 2-level directory cliques;
(3)~\texttt{Beheshtian-BatchStop4}~\cite{beheshtian2022software}, adapting the \texttt{BatchStop4} rule (bisect while $|B|>4$, expand $|B|\le 4$ directly to singletons, no retry) to $W{=}8$ exact-tree queues;
(4)~\texttt{Bors-BatchBisect}~\cite{borsng2023}, modeling historical \texttt{bors-ng}'s single staging branch ($W_{\text{eff}}{=}1$, FIFO $K{\le}8$, depth-first bisection, zero stale rechecks) explicitly distinct from active \texttt{rust-lang/bors} manual rollups~\cite{rustbors2026};
(5)~\texttt{GitHubMQ-StagedGroup}~\cite{github2026mergequeue}, modeling documented \texttt{ALLGREEN} cumulative staged entries ($D{\le}4$, immediate eviction on head failure, cancel-and-rebuild downstream stages, no bisection or auto-retry);
(6)~\texttt{PRediBatch-RiskGroup}~\cite{jungwirth2026predictive}, a PRediBatch-inspired single-timeline stacked policy grouping low-risk PRs ($r<0.55$) under a survival budget ($\ge 0.55$, $K{\le}8$) while isolating high-risk singletons; and
(7)~\texttt{Aviator-DirAffected}~\cite{aviator2026targets}, routing PRs by direct 2-level directory targets into parallel linear lanes ($D{\le}4$) with bridge barriers while enforcing strict global exact-tree stale rechecks across lanes.

\textbf{Missing inputs and explicit omissions.} Our coverage sheet records eight unavailable or out-of-scope variants: original PRediBatch's proprietary BMW feature schema and supervised ML classifier (v7 traces lack historical CI verdicts); production Aviator/Trunk \emph{trust-target-isolation} and Bazel build graphs (which relax exact-tree equality and permit cross-directory escapes without a sound build graph); Uber SubmitQueue's closed conflict analyzer and multi-lane non-exact-tree trees; active \texttt{rust-lang/bors} human \texttt{rollup} labels; GitHub MQ \texttt{HEADGREEN} patch masking and elastic runners; supervised Beheshtian \texttt{RiskBatch}~\cite{beheshtian2022software} and long-horizon Kamath \texttt{LWD}~\cite{kamath2025lightweight}; post-merge SBFL/LLM culprit locators (\texttt{Fonte}~\cite{an2023fonte}, \texttt{SemBIC}~\cite{chen2025sembic}); and per-test longitudinal flakiness scorers (Apple~\cite{kowalczyk2020modeling}, Meta PFS~\cite{machalica2020probabilistic}, FlakeFlagger~\cite{alshammari2021flakeflagger}). None of our modeled comparators is a benchmark of a hosted commercial service.

\subsection{Why membership partition precludes causal cross-architecture ranking}
A subtle property of the paired fault oracle (\texttt{GroundTruth.culprits}) governs valid causal inference across families. Persistent pair conflicts (3\% of conflicting pairs) trigger whenever one endpoint sits in \texttt{job.members} and the other sits in \texttt{mainline} (including speculative \texttt{job.prefix}). By contrast, \textbf{transient intra-batch pair conflicts (97\% of sampled pairs) trigger only among PRs placed together inside \texttt{job.members}}. Consequently, changing queue architecture changes how the same stream is partitioned between \texttt{job.members} and \texttt{job.prefix}: \texttt{GitHubMQ-StagedGroup} and \texttt{Aviator-DirAffected} place 1~PR in \texttt{job.members} atop a \texttt{prefix} (avoiding transient pair faults altogether), \texttt{FIFOOutcomeTree} tests small nodes atop \texttt{prefix}, \texttt{PRediBatch-RiskGroup} tests risk batches atop \texttt{prefix}, \texttt{SpeculativeLinear} passes the full cumulative prefix as \texttt{job.members}, and Family~A policies co-batch PRs inside \texttt{job.members}. We therefore \textbf{restrict causal contrasts strictly to within-family pairs sharing identical membership-partition semantics}---primarily \texttt{SSMQ-FilteredCone} vs.\ \texttt{SSMQ-NoCone}, unfiltered \texttt{SSMQ} vs.\ \texttt{SSMQ-NoCone}, and \texttt{Beheshtian-BatchStop4} vs.\ \texttt{StaticBatchBisect}---and treat cross-family numbers purely as descriptive protocol profiles.

\subsection{Sensitivity regimes, inference, and executable experiments}
Alongside nominal and saturated loads, we evaluate two non-circular controls with uniform unary risk (\texttt{risk\_correlation=0}): \emph{directory proxy} (conflict pairs derived from evaluation directories) and \emph{uniform null} (uniform random pairs), plus the v7 fixed-budget recall sweep ($0\%$--$100\%$). Across 60 paired blocks (20 seeds $\times$ 3 repos), we report survivor P95 latency, root width, clean FRR, accepted PRs, CI-min/merge, and stale rechecks; uncertainty uses 10,000 paired seed-block bootstrap draws retaining equal repository weight plus exact two-sided sign tests.

Separately, the executable Git factorial crosses two packing policies (FIFO or file-disjoint, $K{\le}4$) with three recovery policies (bisection, weight-matched file ranker, AST ranker) on a 13-function Python repository using role-neutral PR IDs (\texttt{pr\_00}..\texttt{pr\_11}) across both ascending and descending polarities (10 seeds $\times$ 2 polarities = 20 paired streams/arm, 120 replays). A concurrent two-worktree protocol checks whether accepting a stale pass breaks \texttt{main} versus an exact-tree recheck. Finally, we evaluate suspect ranking on the 86-batch authored Python fixture and 6 upstream QuixBugs faults~\cite{lin2017quixbugs} across sibling-distractor, same-function, and two-fault regimes under paired ID reversals (36 cases, one knapsack input exceeds memory cap).
