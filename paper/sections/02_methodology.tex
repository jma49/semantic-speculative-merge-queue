\section{SSMQ Architecture and Methodology}
\label{sec:methodology}

SSMQ schedules approved PRs across $W$ parallel CI workers while enforcing a cumulative mainline safety invariant: every merged batch must pass CI on the current mainline snapshot, and if a concurrent commit introduces a persistent interaction before merge, the affected job is automatically rebased and re-verified before landing.

\subsection{Warm-Up Dependency Graph and Risk Scoring}
To prevent temporal data leakage, SSMQ constructs its observed dependency graph $\hat{G}=(V,\hat{E})$ strictly from the chronological warm-up prefix (earliest $25\%$ of merged PRs). For each touched file $f \in F(p)$, $\hat{G}$ indexes historical co-change cliques $\mathcal{N}_{\text{cochange}}(f)$ and two-level directory modules $\mathcal{N}_{\text{mod}}(\mu(f))$, yielding impact cone:
\begin{equation}
C(p) = F(p) \cup \bigcup_{f \in F(p)} \big( \mathcal{N}_{\text{cochange}}(f) \cup \mathcal{N}_{\text{mod}}(\mu(f)) \big).
\end{equation}
Each PR also receives a normalized risk score $r(p) \in [0, 1]$ weighting warm-up-scaled log LOC churn ($0.45$), changed-file count ($0.30$), and maximum file centrality ($0.25$).

\subsection{Graph-Disjoint Multi-Lane Batching}
When a CI slot opens, SSMQ always includes the queue head $p_h$ to prevent starvation:
\begin{itemize}
    \item \textbf{Protected Lane}: If $r(p_h) \ge 0.55$ or $p_h$ was previously deferred due to cone overlap, it runs in a small protected batch (size $\le 2$) of mutually disjoint protected PRs.
    \item \textbf{Fast Lane}: Otherwise, SSMQ greedily packs up to $K_{\max}=8$ low-risk PRs with zero pairwise impact-cone intersection ($C(p_j) \cap \bigcup_{u \in B} C(u) = \emptyset$). Skipped overlapping PRs are marked protected to bound wait time.
\end{itemize}
Crucially, because real warm-up graphs cannot capture every cross-module coupling, SSMQ does \emph{not} assume $\hat{G}$ is complete: off-graph latent conflicts are handled safely by CI verification and causal fault isolation.

\subsection{Two-Regime Beta-Binomial Flaky Gating}
Unconditional batch retries waste CI cycles on true defects, whereas omitting retries causes innocent PRs to be falsely rejected when transient flakes occur. SSMQ updates an online $\mathrm{Beta}(\alpha, \beta)$ posterior ($\alpha_0=1, \beta_0=19$) from observable outcomes (passes increment $\beta$; failures later confirmed transient by a passing retry increment $\alpha$). Upon failure attempt $m \le 2$, SSMQ computes:
\begin{equation}
P(\text{transient} \mid \text{fail}_m) = \frac{(1 - \hat{q}(B))\, P_{\text{flake}}(m \mid \alpha, \beta)}{\hat{q}(B) + (1 - \hat{q}(B))\, P_{\text{flake}}(m \mid \alpha, \beta)}.
\end{equation}
SSMQ applies a \emph{two-regime threshold}: for singletons ($|B|=1$) facing irreversible rejection, retry fires at $P(\text{transient} \mid \text{fail}_m) \ge 0.25$; for multi-PR batches ($|B|>1$), full-batch retry fires only when $P(\text{transient} \mid \text{fail}_m) \ge 0.50$, avoiding wasteful retries on genuinely defective batches.

\subsection{AST/Traceback 1-Step Causal Blame Attribution}
When a multi-PR batch fails deterministically, SSMQ invokes \texttt{ASTStackCausalRanker} before falling back to binary bisection. The ranker parses the failing test traceback to extract implicated files, line frames, and failing test targets, expands a 1-hop AST call graph across repository modules, and scores each PR by whether its AST-level modified functions (filtering comment-only edits) intersect the failing execution cone. SSMQ dispatches two concurrent jobs: $B \setminus \{s_1\}$ (expected to pass in one round) and $\{s_1\}$ in isolation (confirming rejection if defective, or allowing safe isolated merge if the failure was a rebase-resolvable pairwise conflict). If $B \setminus \{s_1\}$ still fails, SSMQ falls back deterministically to binary bisection prioritizing the half containing $s_2$.
