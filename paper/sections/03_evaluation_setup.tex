\section{Evaluation Setup}
\label{sec:eval_setup}

\subsection{Real Open-Source PR Traces}
To ground our simulation in realistic file-touch topology, module hotspots, and bursty arrival profiles, we collected 600 real chronologically merged pull requests via the GitHub GraphQL API from three diverse, large-scale open-source repositories:
\begin{itemize}
    \item \texttt{kubernetes/kubernetes} (Go distributed systems monorepo): 200 PRs, 620 unique touched files, mean 5.82 files/PR.
    \item \texttt{microsoft/TypeScript} (TypeScript compiler): 200 PRs, 1,007 unique touched files, mean 8.48 files/PR, characterized by dense hotspot overlap in core compiler directories.
    \item \texttt{vercel/next.js} (full-stack web framework): 200 PRs, 1,460 unique touched files, mean 9.59 files/PR.
\end{itemize}
For each trace, the earliest $25\%$ of PRs ($50$ PRs) form the chronological warm-up set used strictly to learn $G$, and the remaining $75\%$ ($150$ PRs) form the evaluation arrival stream. Relative inter-arrival gaps from real merge timestamps are preserved and normalized to a $1\times$ baseline of $6.0$ PRs/hr, then scaled by velocity multiplier $v \in \{1\times, 3\times, 5\times, 10\times\}$ to emulate AI-coding-agent PR surges (up to $60$ PRs/hr).

\subsection{Paired Ground Truth and Baselines}
To eliminate confounding variance across algorithms, we employ a \emph{paired experimental design}: for each random seed $s$, deterministic cryptographic hashing assigns identical PR defect labels (calibrated to mean $q = 8\%$, weighted by PR risk score) and identical pairwise semantic conflicts ($P(c_{ij}) = 22\%$ exclusively on pairs with non-empty impact-cone intersection) shared across all evaluated strategies. CI worker capacity is $W=8$, with Gaussian build durations $\mathcal{N}(12.0, 2.0^2)$~min.

We compare \textbf{SSMQ} against five baselines and three ablations:
\begin{itemize}
    \item \texttt{SerialQueue}: Strict FIFO single-PR verification ($W=1$).
    \item \texttt{StaticBatchBisect}: FIFO batches up to $K_{\max}=8$ with recursive $O(\log K)$ binary bisection on failure (Bors / GitHub Merge Queue)~\cite{fallahzadeh2023accelerating}.
    \item \texttt{SpeculativeLinear}: Linear speculative merge train up to depth $4$, aborting and re-queuing all downstream nodes upon head failure (GitLab Merge Trains / Mergify).
    \item \texttt{UberSubmitQueue}: Risk-budgeted speculative batch/tree execution with parallel bisection hedging on risky roots, modeled after Uber's SubmitQueue~\cite{ananthanarayanan2019keeping}.
    \item \texttt{FlakeAwareBatch}: FIFO batching paired with unconditional single-retry deflaking prior to bisection, inspired by flake-aware culprit finding~\cite{henderson2023flake}.
    \item \texttt{SSMQ-NoGraph}, \texttt{SSMQ-NoFlaky}, \texttt{SSMQ-NoBlame}: Controlled ablations disabling each SSMQ mechanism individually.
\end{itemize}

\subsection{Sealed Reproducibility and A/A Noise Calibration}
Following sealed-evaluation best practices, every experimental suite executes across $20$ deterministic seeds per repository ($60$ paired runs per configuration), writing raw outputs and SHA-256 checksums to immutable \texttt{runs/<run\_id>/manifest.json} files. A zero-LLM deterministic auditor verifies all manifests, checks \TotalEscapedDefects{} escaped defects across all \TotalSealedRecords{} runs, computes $95\%$ bootstrap confidence intervals and Cliff's $\delta$ effect sizes, and emits all LaTeX macros (\texttt{generated/numbers.tex}) and tables automatically.

Prior to comparing algorithms, \texttt{exp0\_aa\_noise\_v1} runs two disjoint 20-seed blocks (Block A vs.\ Block B) on identical SSMQ settings to gauge seed-sampling stability. Block A and Block B differ by \AANoiseThroughputPct{}\% in throughput, \AANoiseLatencyPct{}\% in P95 latency, and \AANoiseComputePct{}\% in CI compute cost, providing a baseline reference against which major policy gains (such as the \LatRedVsStaticPct{}\% P95 reduction vs.\ static batching) can be distinguished from minor ablation deltas (such as \texttt{SSMQ-NoBlame}'s small compute margin).
