\section{Discussion, Deployment Guidance, and Threats to Validity}
\label{sec:threats}

\subsection{Practical Deployment Blueprint for High-Velocity CI}
Our empirical findings translate directly into four actionable design rules for teams operating GitHub Merge Queue, GitLab Merge Trains, Bors, or Zuul:
\begin{enumerate}
    \item \textbf{Prioritize Dependency-Disjoint Batching Over Deeper Speculation}: Even a faithful EuroSys~'19 outcome-tree SubmitQueue~\cite{ananthanarayanan2019keeping} suffers \UberInvalidRatePct{}\% branch invalidation when FIFO batches bundle colliding edits. A lightweight warm-up co-change and two-level directory graph requires zero build-system instrumentation, runs in sub-millisecond time, and yields substantial P95 and compute wins even at $40\%$ graph recall.
    \item \textbf{Guard Singletons, Not Multi-PR Batches, Against Flakes}: Measuring merge queues solely on survivor latency hides false rejections of innocent PRs. Applying an asymmetric retry policy ($\tau_1 = 0.25$ on singletons before rejection, $\tau_B = 0.50$ on multi-PR batches) eliminates the majority of flaky developer frustration without triggering \texttt{FlakeAwareBatch}'s tail-latency explosion.
    \item \textbf{Use Deterministic AST/Traceback Blame as a Zero-Latency First Stage}: Our 64-batch executed micro-benchmark demonstrates that AST symbol filtering eliminates co-file documentation noise (\BenchASTCofilePct{}\% vs.\ \BenchFileCofilePct{}\% for file-level overlap) in \BenchASTMs{}~ms. Production queues should deploy deterministic AST/traceback ranking first, reserving heavier LLM fault-localization agents~\cite{jambigi2025fault} strictly for ambiguous multi-culprit or cross-service failures.
    \item \textbf{Extending to Multi-Culprit Top-$k$ Eviction}: Our RQ5 regime analysis revealed that single-suspect eviction ($k=1$) saturates once batch defect density exceeds $20\%$ at $K=12$. Extending Algorithm~\ref{alg:blame} to evict Top-$k$ suspects whenever $\text{score}(s_2) / \text{score}(s_1) > 0.8$ (or capping $K_{\max}$ adaptively as an inverse function of observed batch failure rate) is a straightforward enhancement for noisy branches.
\end{enumerate}

\subsection{Threats to Validity}
\textbf{Construct Validity.} First, although file topologies, hotspot distributions, and relative inter-arrival gaps are mined from 600 real merged GitHub PRs, GitHub GraphQL caps per-PR file lists at 40 files, and merged PR histories omit abandoned PRs and exact enqueue timestamps. Second, while v3 decouples the ground-truth conflict oracle $G^*$ from $\hat{G}$ via off-graph latent conflicts and enforces cumulative mainline verification for persistent conflicts, defect rates and pairwise conflict probabilities are parameterized rather than extracted from private corporate CI logs. Third, our executable blame micro-benchmark validates \BenchTotalBatches{} real failing batches on a six-module Python codebase; polyglot monorepos with asynchronous RPCs, C++/Go template instantiation, or distributed crash traces may exhibit lower deterministic Top-1 accuracy (which our $50\%$--\BenchASTTopOnePct{}\% sweep shows SSMQ tolerates gracefully via bisection fallback).

\textbf{Internal and Conclusion Validity.} Matched paired $(\text{repo}, \text{seed})$ ground truth, disjoint 20-seed A/A noise calibration, bootstrap $95\%$ CIs, Holm-Bonferroni-adjusted Wilcoxon signed-rank tests, and Cliff's $|\delta|$ effect sizes guard against stochastic bias and multiple-comparison inflation. Because each trace drains a finite 150-PR evaluation window rather than an infinite-horizon stationary arrival process, P95 latency characterizes finite-burst service latency rather than steady-state queueing stability.

\textbf{External Validity.} Repositories with heterogeneous CI build-time distributions (e.g., selective build caching where small diffs build $10\times$ faster than full rebuilds) or multi-hour hardware-in-the-loop test benches may require tuning $K_{\max}$, $\theta_{\text{risk}}$, and $(\tau_1, \tau_B)$. Furthermore, our micro-benchmark models Python ASTs; deploying \texttt{ASTStackCausalRanker} in Go or TypeScript monorepos requires language-specific parsers (e.g., Tree-sitter). Evaluating SSMQ in a live shadow deployment atop GitHub Merge Queue on an active open-source repository is our immediate engineering next step.
