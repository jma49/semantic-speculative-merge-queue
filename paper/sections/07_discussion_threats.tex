\section{Interpretation and Limits}
\label{sec:threats}
\textbf{Cost of a moving base.} The simulator represents a tree by the set of integrated PRs. It checks equality of the tested and prospective sets at commit; this abstraction omits order-sensitive patch application and external build inputs. The separate Git fixture uses actual revisions and test executions. On the simulated traces, smaller unstacked batches advance the base more frequently and incur repeated validation. The stacked comparator also changes scheduling and cancellation behavior, so the observed policy difference cannot isolate an effect attributable solely to stacking. Testing conflict-aware ordering inside a stacked train remains an open comparison.

\textbf{Cone explosion and flaky-gate censoring.} Unfiltered warm-up co-change cliques inflate pairwise edge density to 59.1\%--92.4\% because refactor PRs touching hundreds of files link unrelated subsystems. Filtering mega-commits or thresholding co-change weights could preserve wider batches, though doing so trades recall for batch width and still cannot eliminate unstacked stale-base invalidation. Separately, Algorithm~\ref{alg:flaky} updates $\mathrm{Beta}(\alpha,\beta)$ only on confirmed non-stale passes and censors split, stale, and rejected runs, which can underestimate suite flakiness when multi-PR batches split rather than retry.

\textbf{Survivor selection, load, and trace validity.} Survivor P95 measures only accepted changes: \emph{FIFO batch + bisect} looks faster than retry-matched FIFO largely because repeated stale rechecks without retry reject 9.48\% of clean PRs (vs.\ 3.76\%). Reporting FRR, accepted counts, root widths, and per-repository contrasts alongside P95 makes this trade-off visible. Finite trace bursts have startup and drain phases; historical merge times, synthetic Gaussian CI durations, decoupled fixed priors, and one 200-PR window per repository constrain external validity. Paired bootstrap intervals reflect variability across simulation seeds conditional on these three repositories, not generalization across arbitrary projects.

\textbf{Attribution scope and prototype limits.} Function-level AST ranking shows its clearest advantage over a weight-matched file-level ranker when two PRs in a failing batch edit different functions of the same file---an event prevented by file-disjoint packing itself. Our AST ranker covers synchronous bare-name Python \texttt{FunctionDef} nodes and 1-hop bare calls, excluding methods, \texttt{async} functions, module-level code, and dynamic dispatch, whereas the public workload traces come from Go and TypeScript repositories. Furthermore, the Git factorial runs serially on one 13-function authored Python fixture without injected flakiness or concurrent workers, and the 6 QuixBugs faults use authored \texttt{pass} distractors in one combined module; neither estimates operational ranking accuracy on industrial repositories.
