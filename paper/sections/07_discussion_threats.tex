\section{Interpretation and Limits}
\label{sec:threats}
\textbf{Separation and verification answer different questions.} Avoiding a predicted collision may save a failed test today yet expose a persistent incompatibility when the second change reaches the branch tomorrow. Serializing two individually valid PRs repairs only interactions that actually disappear after serialization. A deployable queue needs a check on the combined state and an atomic branch update conditioned on the tested base. The experiment exercises a controlled advancement order. Multiple writers, force pushes, suite changes, and external build inputs would require additional coordination.

\textbf{Selection affects latency.} Survivor latency measures the experience of accepted changes. A policy that rejects difficult candidates can look fast by removing them from its denominator. We therefore report accepted changes and runner work alongside latency. Finite trace bursts have startup and drain phases. Their throughput says little about the stability region of a continuously loaded service. Historical merge times, a simulated duration distribution, and one sample window per repository constrain generalization. The replication units for the paired scheduler comparisons are simulation seeds conditional on these repositories. More seeds cannot supply additional independent projects.

\textbf{Prediction remains the main empirical uncertainty.} Directory membership, identical paths, and co-change are distinct structural relations. Large refactors can make the historical graph dense; a new cross-module dependency can be absent from it. In the controlled recall experiment some simulated labels are explicitly placed on graph edges. Varying this placement measures sensitivity to an assumption. The separate structural control avoids reading scheduler cones when generating labels, yet shares file-system structure with the predictor. Neither supplies labeled CI interference for the sampled public changes. A deployment study would require archived queue admissions, base revisions, test outcomes, and outcomes for plausible alternate groupings.

\textbf{Attribution depends on the available observation.} A traceback concentrated on one function helps distinguish two edits to different functions of the same file. Weak traces, dynamic dispatch, same-function edits, and coincident failures can make the suspects indistinguishable. The ranker uses Python function names and a shallow call relation. The workload traces come from repositories using other languages; ranking results come exclusively from executable fixtures. A passing leave-one-out run establishes that the complement passed the available suite on that base. Latent defects and interactions beyond the suite remain possible.
