\section{Introduction}
\label{sec:intro}

Continuous Integration (CI) guards mainline branches against functional regressions and build breakages~\cite{hilton2016usage,zhao2017impact,bernardo2023impact,wessel2023github}. At high submission velocities---amplified by automation and agent-authored pull requests (PRs)---serial mainline verification bottlenecks delivery: a $12$~min test suite caps serial throughput below $5$~PRs/hr regardless of runner fleet size. Organizations therefore deploy batched and speculative merge queues, including Google's TAP~\cite{elbaum2014techniques,memon2017taming}, Uber's SubmitQueue~\cite{ananthanarayanan2019keeping}, Meta's lean pipelines~\cite{juloori2025scale}, Bors, GitHub Merge Queue, and GitLab Merge Trains~\cite{fallahzadeh2023accelerating,jungwirth2025improving}.

While regression test selection shortens individual builds~\cite{leong2019assessing,machalica2019predictive,jin2023hybridcisave,schwendner2025practical}, standard hosted queues (Bors, GitHub Merge Queue, GitLab Merge Trains) form batches strictly in arrival (FIFO) order; even conflict-graph speculation trees such as Uber's SubmitQueue~\cite{ananthanarayanan2019keeping} expend runner capacity speculating across intersecting branches that fail together. Auditing 600 chronologically merged PRs from \texttt{kubernetes/kubernetes}, \texttt{microsoft/TypeScript}, and \texttt{vercel/next.js} (Section~\ref{sec:background}), we find that \emph{every consecutive 8-PR FIFO window} (\TraceFifoOverlapPct{}\%) contains at least one two-level directory collision, even though mutually disjoint 4-PR subsets exist in \TraceNextDisjPct{}\% of rolling windows on \texttt{next.js} and \TraceKbsDisjPct{}\% on \texttt{kubernetes}. Co-scheduling coupled PRs invites \emph{semantic merge conflicts} that pass pre-submit checks individually yet fail integration together~\cite{zhang2022trained,svyatkovskiy2022program}, while \emph{flaky tests}~\cite{luo2014empirical,bell2018laker,lam2019idflakies,lam2020large,parry2025systemic} trigger either clean-PR false rejections or expensive batch retries~\cite{henderson2023flake,najafi2019bisecting}.

Conditional on a clean base commit $M_0$ (distinct from persistent base-conflict edges against $M_0$), independent PR defect rates $q_i$, pairwise conflict probabilities $P(c_{ij})$ across coupled edges $E(B)$, and a false-failure-only flake rate $\phi$, the first-attempt pass probability of batch $B$ ($K=|B|$) is:
\begin{equation}
P(\text{pass} \mid B, M_0) = (1 - \phi) \prod_{i \in B}(1 - q_i) \prod_{(i,j) \in E(B)}(1 - P(c_{ij})).
\label{eq:survival}
\end{equation}
When $E(B)$ is unconstrained, colliding pairs grow quadratically in $K$, eroding $P(\text{pass}\mid B, M_0)$ and turning speculation into wasted compute.

We present \textbf{SSMQ (Semantic Speculative Merge Queue)}, targeting Eq.~\eqref{eq:survival} through three mechanisms:
\begin{enumerate}
    \item \textbf{Graph-Disjoint Risk-Stratified Batching} eliminates observed edges $\hat{E}(B)$. Using a leak-free dependency graph $\hat{G}$ and P90 risk scales learned strictly from chronological warm-up commits, SSMQ packs cone-disjoint low-risk PRs into fast lanes ($K \le K_{\max}$) while isolating colliding or high-risk PRs in starvation-bounded protected lanes ($K \le 2$).
    \item \textbf{Two-Regime Beta-Binomial Flaky Gating} estimates suite flakiness online via a plug-in $\mathrm{Beta}(\alpha,\beta)$ heuristic with asymmetric thresholds---guarding singletons before permanent rejection ($\tau_1 = 0.25$) while suppressing full-batch reruns below $\tau_B = 0.50$.
    \item \textbf{Fail-Safe 1-Step AST/Traceback Suspect Ranking} ranks deterministic multi-PR failures via \texttt{ASTStackCausalRanker}, combining AST function-symbol diffs with specificity-weighted 1-hop test call graphs in \BenchASTMs{}~ms and falling back deterministically to prioritized binary bisection.
\end{enumerate}

We pair \emph{subprocess test execution} with \emph{non-circular discrete-event trace replay}. First, across \BenchTotalBatches{} executed failing Python \texttt{unittest} batches---including \BenchSiblingBatches{} functional sibling-function co-file distractors with balanced churn and counterbalanced PR IDs---\texttt{ASTStackCausalRanker} reaches \BenchASTTopOnePct{}\% Top-1 accuracy and \BenchASTLOOPct{}\% executed leave-one-out recovery, versus \BenchFileTriviaTopOnePct{}\% Top-1 (\BenchFileTriviaSiblingPct{}\% vs.\ \BenchASTSiblingPct{}\% on functional siblings) for a same-information, trivia-filtered file baseline. Second, across \TotalSealedRuns{} SHA-256-sealed suites (\TotalSealedRecords{} replays over 450 evaluation PRs, \TotalEscapedDefects{} within-model cumulative escapes), we decouple the conflict oracle $G^*$ from $\hat{G}$ at \emph{fixed conflict density} ($\rho \in [40\%, 100\%]$ plus a $P_c=0$ control) against six baselines including static FIFO batching and FIFO and dependency-aware outcome-tree proxies~\cite{ananthanarayanan2019keeping}.

Four findings stand out: (a)~SSMQ lowers mean P95 merge latency by \LatRedVsStaticPct{}\% vs.\ static FIFO batching (\SSMQPNinetyFiveLat{} vs.\ \StaticPNinetyFiveLat{}~min, Holm $p\HolmPLatVsStatic{}$, $|\delta|=\CliffsLatVsStatic{}$) and \LatRedVsDepTreePct{}\% vs.\ dependency-aware outcome trees (\DepTreePNinetyFiveLat{}~min), driven primarily by cone-disjoint packing; (b)~gains persist when $60\%$ of conflicts lie off-graph ($\rho=40\%$) and reverse cleanly at $P_c=0$; (c)~asymmetric Beta-Binomial gating outperforms no-retry and matched fixed-retry variants across $\phi \in [0\%, 15\%]$; and (d)~because proactive packing keeps failed root batches small (\FacEightKEightFailSz{}~PRs), 1-step blame adds only a modest, non-significant (\FacEightKEightGainPct{}\%--\FacSixteenKEightGainPct{}\%, Holm $p \ge 0.118$) end-to-end latency delta inside SSMQ, clarifying its role as fast wide-batch and developer culprit localization.

This paper makes four contributions:
\begin{itemize}
    \item \textbf{Empirical Trace Audit}: Locality analysis of 600 merged PRs across Kubernetes, TypeScript, and Next.js showing universal FIFO-8 collisions alongside non-FIFO disjointness (Section~\ref{sec:background}).
    \item \textbf{SSMQ \& Scoped Analysis}: Scheduling algorithms with within-model cumulative safety, fresh-batch dispatch bounds, and unary vs.\ multi-culprit recovery bounds (Section~\ref{sec:methodology}).
    \item \textbf{Executable 80-Batch Blame Benchmark}: Live-timed Python \texttt{unittest} suite with functional sibling co-file distractors and leave-one-out recovery (Section~\ref{sec:results}, RQ1).
    \item \textbf{Deconfounded Sealed Evaluation}: \TotalSealedRuns{} SHA-256-sealed suites (\TotalSealedRecords{} replays), fixed-density recall sweeps, matched ablations, and a replication package (Sections~\ref{sec:eval_setup}--\ref{sec:results}).
\end{itemize}
